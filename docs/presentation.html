Export 기능 v2.8 신기능 소개
발표자: 개발팀  |  2026년 5월 4일  |  약 20분
안녕하세요. 오늘은 유진홈센터 DB 텔레그램 봇 프로젝트에서 이번 세션에 완료한 Export 기능 개선 내용을 공유드리겠습니다. 총 세 가지 신기능과 그 배경을 20분 안에 다루겠습니다.

02배경 & 문제

프로젝트 목적

  • 유진홈센터(EHC Mall) DB 테이블·컬럼을 텔레그램으로 조회
  • 프로젝트별 관련 테이블을 CSV/PDF로 자동 수집 → 전송
  • OpenClaw 에이전트 + FastAPI + Telegram Bot 조합

누적 불편 사항

  • 여러 도메인 테이블이 섞여도 경고 없이 전송됨
  • PDF 요약 텍스트가 파일 안에만 있어 채팅에서 파악 불가
  • 에이전트 분기(도메인 vs 키워드 vs 직접 지정) 규칙 불명확
해결한 문제
  • 도메인 혼입 여부를 stdout에 즉시 경고
  • summary·추천 구성안을 텔레그램에 자동 전송
  • SKILL/SOUL 문서에 분기 체크리스트 추가
봇을 운영하다 보니 세 가지 불편함이 반복됐습니다. 첫째, 서로 다른 도메인 테이블이 한 파일에 섞이는 경우가 있는데 아무 경고가 없었습니다. 둘째, 에이전트가 PDF 요약을 만들어 파일에 넣는데, 채팅 창에서 바로 확인이 안 됐습니다. 셋째, 에이전트가 도메인 전체 요청인지 키워드 검색인지 헷갈려서 잘못된 분기로 실행하는 경우가 있었습니다. 이번 v2.8에서 이 세 가지를 한꺼번에 개선했습니다.

03시스템 아키텍처

┌────────────────────────────────────────────────────────┐ │ 사용자 (텔레그램) │ └──────────────────────────┬─────────────────────────────┘ │ 메시지 수신 / 파일·텍스트 전송 ┌──────────────────────────▼─────────────────────────────┐ │ OpenClaw 에이전트 (이 PC) │ │ SOUL.md + SKILL_export.md → exec export_tables.py │ └─────────────────────────┬──────────────────────────────┘ ┌────────────┴────────────┐ ▼ ▼ ┌─────────────────┐ scripts/ ┌──────────────────────┐ │ FastAPI :8000 │◄──────────►│ export_tables.py │ │ /v1/search │ │ → CSV / PDF 생성 │ │ /v1/explain │ │ → sendMessage (NEW) │ │ /v1/tables │ │ → sendDocument │ └─────────────────┘ └──────────────────────┘ ▲ ┌─────────────────┐ │ ehcmall_index │ │ .json (data/) │ └─────────────────┘
전체 구조는 세 부분으로 나뉩니다. 사용자가 텔레그램으로 요청을 보내면 OpenClaw 에이전트가 SKILL/SOUL 문서를 읽고 export_tables.py를 exec로 실행합니다. 스크립트는 로컬 FastAPI 서버(포트 8000)에서 메타데이터를 가져와 CSV 또는 PDF를 만들고, 이번에 추가된 sendMessage로 요약 텍스트를 먼저 보낸 뒤 sendDocument로 파일을 전송합니다. FastAPI는 미리 만들어둔 ehcmall_index.json만 읽으므로 실제 DB에 직접 접근하지 않습니다.

  • /v1/overview — DB 전체 개요

  • NEW도메인 혼입 경고
SKILL / SOUL 문서
  • SKILL_export.md — 에이전트 분기 규칙
  • SOUL.md — exec 순서 강제 규칙
  • exec 전 분기 체크리스트
  • 채팅 직접 출력 금지 이유 명시
스크립트역할

컴포넌트를 세 그룹으로 보면 됩니다. FastAPI 서버는 인덱스 파일만 읽고 JSON을 돌려주는 단순한 구조입니다. export_tables.py가 핵심인데, 이번에 sendMessage 래퍼와 도메인 경고가 추가됐습니다. SKILL/SOUL 문서는 에이전트가 어떤 경로로 exec를 실행할지 규칙을 정의합니다. scripts/ 폴더에는 역할별로 분리된 네 개 스크립트가 있습니다.

05API 엔드포인트

엔드포인트 설명 export에서 사용
GET /v1/search?q=키워드 테이블명·도메인·설명 키워드 검색 1단계 후보 수집
GET /v1/explain?table=명 테이블 전체 메타 + 컬럼 목록 CSV/PDF 본문 데이터
GET /v1/tables?domain=도메인 도메인 소속 테이블 전체 목록 --domain 흐름
GET /v1/domains 업무 도메인 목록 및 테이블 수 —
GET /v1/overview DB 전체 개요 (규모·도메인 분포) generate_report.py
GET /health 서버 상태 및 로드된 테이블 수 —

서버 기동 후 http://localhost:8000/docs 에서 Swagger UI로 전체 스펙 확인 가능

export_tables.py가 사용하는 엔드포인트는 세 개입니다. search로 후보를 모으고, explain으로 각 테이블의 상세 정보를 채우고, domain 흐름일 때는 tables 엔드포인트로 해당 도메인 전체를 가져옵니다. 인덱스만 읽으므로 응답이 매우 빠르고, 실제 DB 연결이 없어 안전합니다.

06Export 흐름

필터링 ON — 4단계 흐름 (기본)

1단계--search-json-only
후보 JSON 수집
→
2단계에이전트 선별
(JSON 근거만)
→
3단계summary
추천 구성안 작성
→
4단계export exec
파일 생성·전송

필터링 OFF — 단일 exec

  • "전체 다", "필터링 없이" 발화 시
  • 키워드를 바로 export_tables.py에 전달

--domain 흐름

도메인 전체 요청 시
  • "재고 도메인 전체" → --domain 재고
  • /v1/tables?domain=재고 호출 (키워드 검색 금지)
  • 30개 초과 시 범용·로그·임시 테이블 제외
분기 결정 체크리스트 (v2.8 추가)
  1. "도메인 전체/전부/다" → --domain
  2. "필터링 없이/전체 다" → 필터링 OFF 단일 exec
  3. 그 외 → 필터링 ON 4단계
export 흐름은 세 갈래입니다. 기본은 4단계 흐름으로, 먼저 --search-json-only로 후보 JSON을 받아 에이전트가 선별하고, summary와 추천 구성안을 작성한 뒤 exec로 파일을 만듭니다. "전체 다"처럼 필터링을 원하지 않으면 키워드를 바로 넘기는 단일 exec를 씁니다. 도메인 전체 요청은 키워드 검색 대신 /v1/tables 엔드포인트를 씁니다. 이 세 분기를 exec 전에 확인하도록 v2.8에서 체크리스트를 추가했습니다.

07신기능 ① 도메인 혼입 경고

기존 동작

  • 다른 도메인 테이블이 섞여도 아무 메시지 없이 전송
  • 수신자가 파일을 열어봐야 도메인 혼입 확인 가능

변경 후 (v2.8)

  • 테이블 수집 완료 후 sendDocument 직전에 stdout 출력
  • 도메인 1개: 정상 안내
  • 도메인 2개 이상: 경고 메시지
# 도메인 1개일 때
[도메인 분포] 재고: 35개

# 도메인 2개 이상일 때
[경고] 도메인 분포: 재고: 35개 | 기준정보: 10개
      — 여러 도메인이 섞였습니다
구현 위치
export_tables.py main() 내
_domain_distribution(rows) 결과를
sendDocument 직전 조건 분기 출력
첫 번째 신기능은 도메인 혼입 경고입니다. 키워드 검색 시 여러 도메인의 테이블이 한 파일에 섞이는 경우가 종종 있습니다. 이제 sendDocument 직전에 _domain_distribution 함수로 도메인 분포를 계산해 1개면 정상 출력, 2개 이상이면 [경고] 표시와 함께 분포를 보여줍니다. 에이전트 로그에서 바로 확인할 수 있어 디버깅이 훨씬 쉬워졌습니다.

08신기능 ② summary 자동 텔레그램 전송

기존 동작

  • --summary 텍스트는 PDF 내부 표지에만 삽입
  • 추천 구성안도 PDF 안에만 존재
  • 채팅 창에서는 파일을 열어야 내용 확인 가능

변경 후 (v2.8)

  • PDF 전송 직전 텍스트 메시지 먼저 발송
  • summary + 추천 구성안을 하나의 메시지로 묶어 전송
  • plain text 전송 (parse_mode 없음) — Markdown 400 오류 방지
# _send_message 신규 함수
def _send_message(token, chat_id, text):
    url = f"{TG_API_BASE}/bot{token}/sendMessage"
    body = json.dumps({
        "chat_id": str(chat_id),
        "text": text,
        # parse_mode 없음 (plain text)
    }).encode("utf-8")
    ...
# main() 전송 흐름
if args.format == "pdf":
    intro_parts = []
    if args.summary:
        intro_parts.append(f"리포트 요약: {args.summary}")
    if rec:
        intro_parts.append(rec)
    if intro_parts:
        _send_message(token, chat_id,
            "\n\n".join(intro_parts))
_send_document(token, chat_id, out_path, ...)
두 번째 신기능은 summary 자동 전송입니다. 에이전트가 --summary와 --recommendation 인자를 넣어 exec를 실행하면, 스크립트가 PDF 파일을 만들기 전에 텍스트 메시지를 먼저 텔레그램으로 보냅니다. parse_mode를 쓰지 않는 이유는, 추천 구성안에 특수문자가 들어가면 Telegram Markdown 파서가 400 오류를 내기 때문입니다. plain text로 보내면 안전합니다. sendMessage 실패는 경고로만 처리하고 PDF 전송은 계속 진행합니다.

09신기능 ③ SOUL / SKILL 문서 개선

SKILL_export.md 변경

분기 결정 체크리스트 추가 (frontmatter)
  1. "도메인 전체/전부/다/모두" → --domain 사용. 키워드 검색 금지
  2. "필터링 없이" / "전체 다" / "검색 결과 그대로" → 필터링 OFF 단일 exec
  3. 그 외 → 필터링 ON 4단계 흐름

SOUL.md 워크스페이스 규칙 강화

  • PDF exec에 --summary/--recommendation 권장 명시
  • 채팅에 직접 출력 금지 — 구조적 이유 포함
채팅 직접 출력 금지 이유

에이전트가 채팅에 텍스트를 출력하면 그 턴이 끝납니다.
턴이 끝나면 exec를 실행할 수 없습니다.
따라서 summary·추천 구성안을 채팅에 먼저 쓰면
PDF가 전송되지 않는 구조적 문제가 생깁니다.

올바른 순서 (PDF)
  1. 1단계 search exec (JSON 수신)
  2. 에이전트 선별
  3. summary·추천 구성안 exec 인자에만 넣기
  4. 4단계 export exec → 스크립트가 텔레그램 전송
세 번째 개선은 SKILL과 SOUL 문서입니다. SKILL_export.md frontmatter에 체크리스트를 추가해 에이전트가 exec 전에 어떤 분기를 써야 할지 명확히 알 수 있게 했습니다. SOUL 문서에는 채팅에 직접 출력하면 안 되는 구조적 이유를 명시했습니다. 에이전트가 턴 내에서 텍스트를 출력하면 그 턴이 종료되어 exec를 실행할 수 없게 됩니다. summary와 추천 구성안은 반드시 --summary와 --recommendation 인자로만 넘겨야 하고, 스크립트가 _send_message로 자동 전송합니다.

10트러블슈팅 회고

증상 원인 해결
Telegram sendMessage 400 오류 추천 구성안 텍스트에 Markdown 특수문자 포함 parse_mode 제거 → plain text 전송
도메인 전체 요청에 타 도메인 테이블 혼입 키워드 검색 시 설명에 도메인명이 언급된 다른 테이블도 히트 도메인 전체 요청 시 /v1/tables?domain= 전용 흐름 분리
에이전트가 summary를 채팅에 출력 후 exec 누락 채팅 출력 후 턴 종료 → exec 실행 불가 SOUL/SKILL 문서에 순서·금지 이유 명시, 스크립트 자동 전송
--search-json-only 대신 --search-only 사용 에이전트가 두 플래그를 혼동 SKILL 문서에 에이전트용은 반드시 --search-json-only로 명시
한국어 PDF 폰트 깨짐 ReportLab 기본 폰트 미지원 AppleGothic.ttf 등록, 실패 시 stderr 경고 후 영문 폰트 대체
개발 과정에서 마주친 주요 이슈 다섯 가지를 정리했습니다. 가장 반복적이었던 문제는 에이전트가 채팅에 텍스트를 출력한 뒤 exec를 빠뜨리는 것이었습니다. 이를 구조적으로 해결하기 위해 스크립트가 직접 sendMessage를 호출하도록 바꿨습니다. Markdown 400 오류는 특수문자 이스케이프보다 parse_mode를 아예 빼는 게 더 안정적이었습니다. 도메인 혼입 문제는 /v1/search가 설명 텍스트까지 검색하기 때문에 발생했고, 도메인 전체 요청은 /v1/tables 전용 흐름으로 분리해 해결했습니다.

11향후 계획

단기 (1~2주)

  • export 게이트 플러그인 beforeDispatchMode 자동화 안정화
  • --reasons JSON 에이전트 자동 생성 정확도 개선
  • 도메인 혼입 경고 시 사용자 확인 인터랙션 추가

중기 (1개월)

  • PDF 대용량(100+ 테이블) 처리 속도 최적화
  • SKILL_search.md와 SKILL_export.md 연동 강화
  • 다국어 PDF 지원 (영문 컬럼명 병기)
장기 아이디어
  • ETL 변경 감지 → 인덱스 자동 갱신 훅
  • Slack 채널 연동 (Telegram 외 추가)
  • 테이블별 데이터 품질 점수 시각화 (PDF 차트)
  • 에이전트 선별 결과 피드백 루프 (사용자 평가 → 이유 개선)
단기적으로는 이번에 추가된 기능의 안정화가 우선입니다. 특히 에이전트가 자동 생성하는 --reasons 텍스트의 품질을 높이는 것이 중요합니다. 중기적으로는 대용량 PDF 성능과 SKILL 문서 간 연동을 다듬겠습니다. 장기적으로는 인덱스 자동 갱신과 멀티채널 지원을 검토하고 있습니다.
