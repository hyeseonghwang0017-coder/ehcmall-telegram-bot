## Instructions

### 텔레그램 (@EHC_DB_Bot)

이 스킬은 **텔레그램 `accountId=ehcmall`** 로 라우팅된 세션(**@EHC_DB_Bot**)에서만 의미가 있다. `chat_id`는 그 대화의 값을 쓴다. 다른 봇·계정은 OpenClaw 바인딩이 다르므로 이 스킬·SOUL과 짝이 맞지 않을 수 있다.

### Export 요청 — 응답 순서 (최우선 · 위반 시 전부 오답)

**이 절은 SOUL.md의 동일 제목 절과 함께 적용된다. 다른 친절 응답·요약·템플릿보다 우선한다.**

1. **형식별 필수 순서 (위반 시 오답):**
   - **PDF**: ① 1단계 search exec → ② 선별 → ③ summary 텍스트 내부 작성(채팅 출력 금지) → ④ 추천 구성안 텍스트 내부 작성(채팅 출력 금지) → ⑤ 4단계 export exec (`--summary`③, `--recommendation`④ 인자 포함). `--summary`/`--recommendation` 없이 ⑤를 실행하는 것은 오답.
   - **CSV**: ① 1단계 search exec → ② 선별 → ③ 4단계 export exec. 채팅 텍스트 출력 없이 바로 exec.
   - 형식이 애매하면 **한 줄로 CSV vs PDF만** 묻는 것은 허용한다. 그 한 줄 외 테이블명·설명·행 수·점수는 쓰지 않는다.
2. exec가 성공할 때까지 **테이블 목록·설명·컬럼·row_count·score·도메인 분포를 채팅에 적지 않는다.**
   (1단계 `--search-json-only`의 stdout·JSON도 사용자에게 붙여넣지 않는다. 에이전트 내부 판단용만.)
3. 사용자에게 보내는 **성공 응답 본문**은 아래 **「결과 안내」**의 짧은 템플릿과, 필요 시 exec stdout에 있는 경로·카운트 인용만 허용한다.
   그 외 장문 요약·"추가로 이런 테이블도 고려해 보세요" 등은 **금지**한다.
4. exec 실패(exit ≠ 0)면 **stderr를 그대로 인용**한다. 임의로 성공한 척 하거나 표를 만들어 채우지 않는다.

### 규칙 (최우선 · 절대 규칙)

**아래 중 하나라도 위반하면 오답이다.**

- CSV·PDF·리포트(프로젝트별)·파일 export 요청이 들어오면 **반드시 exec로 `export_tables.py`를 실행**한다.
- **PDF 형식**이면 반드시 **summary 텍스트를 내부적으로 작성**하고 그대로 `--summary "..."` 에 넣어 exec를 실행한다. 채팅에 직접 출력하면 그 턴에서 exec를 실행할 수 없게 된다. `--summary` 없이 exec를 하면 오답이다. (CSV는 생략한다.)
- **PDF 형식**이면 반드시 **추천 구성안을 내부적으로 작성**하고 그대로 `--recommendation $'...'` 에 넣어 exec를 실행한다. 채팅에 직접 출력하면 그 턴에서 exec를 실행할 수 없게 된다. `--recommendation` 없이 exec를 하면 오답이다. (CSV는 생략한다.)
- LLM이 테이블 목록·설명·컬럼·행 수·점수를 채팅에 직접 작성하는 것은 **금지**한다. (파일·텔레그램 전송이 결과물이다.)
- "전송 도구가 없다", "직접 내용을 보내드리겠다", "텍스트로 정리해드리겠다", "여기 요약해 드리겠습니다" 등  
  스크립트 실행을 **우회하는 응답은 금지**한다.
- exec가 실패(exit ≠ 0)하면 **stderr 내용을 그대로 인용**해 안내하고, 자체 생성으로 대체하지 않는다.
- **어떤 스크립트를 쓰는지, 왜 그 스크립트를 선택했는지 사용자에게 설명하지 않는다.** "도메인 리포트는 도메인 전용 export로 만들어야 맞습니다" 같은 내부 구현 설명은 금지한다. 바로 exec한다.
- **기존 PDF 파일을 직접 편집하는 것은 절대 금지한다.** PyPDF2·pypdf·pdfplumber 등 PDF 편집 모듈을 시도하지 않는다. 변경 요청이 오면 항상 스크립트를 재실행해서 새 파일을 만든다.
- **재실행 전 사용자 확인을 구하지 않는다.** "~로 다시 만들어드릴까요?" 같은 선택 제시 없이 바로 exec한다.

**금지 응답 예시 (이런 식으로 답하면 안 됨):**

- 프로젝트에 맞는 테이블을 산문으로만 나열하고 끝내기
- 표나 파일 없이 "추천", "고려해 보세요", 번호 목록만 길게 쓰기
- API를 거치지 않은 가상의 `row_count`, `score`, `description`을 적기
- **"간단한", "간략한", "짧은" 수식어가 붙었다고 마크다운·텍스트 파일을 직접 작성하는 것은 금지한다.** "간단한 리포트"도 반드시 exec로 export_tables.py를 실행해서 만든다.

이 스킬에 진입하면 **exec로 스크립트를 돌린 뒤**에만 사용자에게 답한다.  
설명·요약·해석을 **추가로** 만들지 않는다 (파일이 결과물이다).

## 분기 판단

사용자가 **직전 export 결과물을 변경하거나 형식을 바꿔달라**고 요청한 경우:
("컬럼 상세 빼줘", "다시 만들어줘", "섹션 빼줘", "넣어줘", **"pdf로 만들어줘", "pdf로 전송해"** 등 + 이전 대화 컨텍스트에 특정 도메인·프로젝트 export 결과가 있음):
→ **[재생성 — 직전 export 재실행]** 섹션으로 바로 이동. 사용자 확인 없이 즉시 exec.
→ 직전 컨텍스트가 도메인/프로젝트별 export이면 SKILL_report(DB 전체 개요)로 넘어가지 않는다.

사용자가 **"{도메인} 도메인 전체 테이블"**, **"{도메인} 도메인 전부"**, **"{도메인} 도메인 테이블 다"** 등 특정 도메인의 전체 테이블을 명시한 경우:
→ **[도메인 전체 — --domain 흐름]** 섹션으로 이동.

사용자가 **"필터링 없이"**, **"전체 다"**, **"검색 결과 그대로"** 등을 명시한 경우:
→ **[필터링 OFF — 단일 exec]** 섹션으로 바로 이동.

그 외 모든 경우 (기본):
→ **[필터링 ON — 4단계 흐름]** 섹션으로 이동.

## [재생성 — 직전 export 재실행]

직전 대화에서 export가 이미 실행된 뒤, 사용자가 결과물에 변경을 요청한 경우에 적용한다.

### 핵심 규칙

- **PDF 파일을 직접 편집하지 않는다.** PyPDF2·pypdf 등 어떤 PDF 라이브러리도 시도하지 않는다.
- 직전 exec에 사용한 인자를 그대로 유지하고, 요청된 변경 사항에 해당하는 인자만 추가·제거한다.
- 사용자에게 "다시 만들어드릴까요?" 등 확인을 구하지 않고 **즉시 exec한다.**

### 자연어 → 인자 번역 (재생성용)

| 사용자 요청 | 변경 인자 |
|---|---|
| "컬럼 상세 빼줘" / "컬럼 상세 없애줘" / "컬럼 표 지워줘" | `--no-column-details` 추가 |
| "컬럼 상세 다시 넣어줘" | `--no-column-details` 제거 |
| "섹션 추가 / 제거" | 해당 인자 조정 (SKILL_report 자연어 번역표 참고) |

### exec 형식

직전 PDF exec 인자를 그대로 복사하고 변경 인자만 조정해서 실행한다.

**예 — 직전 exec에 `--no-column-details`만 추가:**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_pdf.py {직전과 동일한 인자들} --no-column-details
```

exec 성공 후 답변:
```
📄 컬럼 상세 제외 버전으로 다시 만들어서 보냈습니다.
• 저장 경로: {exec stdout의 파일 경로}
```

## 플러그인 export 게이트(before_dispatch)와 에이전트

`ehcmall-export-gate` 플러그인 설정 **`beforeDispatchMode`** (기본값 **`agent`**)일 때는 게이트가 **아무 것도 하지 않고** 요청이 **대화 LLM**으로 전달됩니다. 에이전트는 아래 **[필터링 ON — 4단계 흐름]** 으로 `/v1/search` JSON(`--search-json-only`)을 exec로 받아 후보 안에서만 테이블을 고르고, **`--tables` + `--reasons`** 로 export합니다.

**`beforeDispatchMode`: `auto-export`** 로 두면 예전처럼 게이트가 `export_tables.py --auto-filter`만 실행하고 그 턴은 **채팅 모델을 호출하지 않습니다**. 이 경우 선별은 스크립트 안쪽(Anthropic/OpenAI 키 또는 휴리스틱)만 사용합니다.

텔레그램에는 **최종 파일 전송 + 짧은 완료 한 줄**만 보이게 한다. 검색 JSON·선별 목록·exec 로그 장문을 채팅에 쓰지 않는다.

```
직전에 받은 테이블 메타 파일의 내용을 바꾸라는 요청이 아니다. 새 파일을 만들거나 export 스크립트를 돌리지 말고, 아래 테이블마다 explain API JSON만 exec로 가져온 뒤, 이 채팅에만 답한다.

〔프로젝트/내가 원한 분석 한 줄〕
…

〔방금 파일에 나온 테이블명, 한 줄에 하나 또는 콤마 구분〕
…

규칙:
- 각 테이블에 대해 ehcmall-db-explain 스킬 규칙대로 `http://127.0.0.1:8000/v1/explain?table=테이블명` 을 exec로 호출한다.
- 선택 이유를 쓸 때는 **그 JSON에 실제로 있는** 도메인·순위·점수·행 수·설명·컬럼 요약만 근거로 쓴다. API에 없는 숫자·문장을 만들지 않는다.
- 각 테이블마다 고객이 읽을 **「선택 이유」2~4문장**(한국어)을 새로 쓴다. 내부 구현·API 경로·휴리스틱·LLM·알고리즘·점수화 같은 말은 쓰지 않는다.
- 답의 맨 끄트머리에, 내가 나중에 `--reasons`로 넣을 수 있게 **JSON 한 덩어리만** 추가한다(코드펜스 없이). 키는 테이블명 정확히, 값은 위에서 쓴 이유 문장.
형식: {"TABLE_A":"…","TABLE_B":"…"}
```

## 공통 — 정보 추출

사용자 메시지에서 다음 세 값을 뽑는다.

- **프로젝트명** (`--project`): 분석 주제 그대로. 예: «재고관리 최적화», «추천시스템 구축», «매출 분석»
  - "매출 도메인에 대한 리포트" → 프로젝트명 `매출 도메인 분석` (「도메인」은 프로젝트명에만, 키워드에는 넣지 않는다)
- **검색 키워드 1~3개**: 프로젝트와 직접 관련된 한국어 핵심 명사.
  - "재고관리 최적화 프로젝트" → `재고`
  - "추천시스템을 구축하려는데 쓸 수 있는 테이블" → `상품 회원 주문` (3개)
  - "매출 분석에 필요한 테이블" → `매출`
  - "매출 도메인에 대한 리포트" → `매출` (「도메인」은 키워드로 쓰지 않는다)
  - **「유통」단어 분기 — 반드시 구분:**
    - 물류·공급망·배송·SCM 최적화 맥락 → `물류 입고 출고` 또는 `물류 공급 배송` (「유통」단독 금지 — 유통기한 테이블에 걸림)
    - 유통기한·제품기한 관리 맥락 → `유통기한` (전체 단어)
    - 유통채널·판매채널 맥락 → `채널 판매`
- **형식** (`--format`): `csv` 또는 `pdf` 중 하나
  - "CSV로", "엑셀로", "스프레드시트로" → `csv`
  - "리포트", "보고서", "PDF로", "분석 리포트", "리포트를 생성해줘", "리포트 생성" → `pdf`
- **chat_id**: 현재 텔레그램 대화의 chat_id (숫자 또는 @아이디)
- **저장 경로** (`--out-dir`, 선택): 사용자가 경로를 지정한 경우에만 추가. 지정이 없으면 생략(기본값 사용).
  - "바탕화면에 저장해줘" / "바탕화면으로" → `--out-dir ~/Desktop`
  - "다운로드 폴더에" → `--out-dir ~/Downloads`
  - "X 폴더에 저장해줘" → `--out-dir X`
  - **저장 경로가 명시된 경우 "기본 경로에 먼저 저장하겠습니다" 등 설명 없이 즉시 해당 경로로 exec한다.**

형식이 모호하면 «CSV로 받으시겠어요, 아니면 PDF 리포트로 만들어 드릴까요?» 한 줄만 묻는다.

## [필터링 ON — 4단계 흐름] (기본 동작)

### 1단계 — `/v1/search` JSON 조회 exec

아래 명령으로 **로컬 메타 API가 반환한 검색 객체**를 JSON으로 stdout에서 받는다. (dedupe는 테이블명 기준·첫 등장 유지.)

```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py --search-json-only 키워드1 [키워드2 키워드3]
```

**예 (추천시스템, 키워드 3개):**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py --search-json-only 상품 회원 주문
```

**예 (재고관리, 키워드 1개):**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py --search-json-only 재고
```

stdout 형식(UTF-8 JSON 한 덩어리):
```json
{
  "keywords": ["상품", "회원", "주문"],
  "results": [ { "...": "각 항목은 /v1/search results[] 원본 필드 그대로" } ]
}
```

`results[].table` 값만 테이블명 후보로 삼는다. JSON에 없는 테이블명을 **새로 지어내지 않는다.**

### 2단계 — 대화 모델 선별 (exec 1단계 JSON만 근거)

1단계 JSON의 **각 객체에 실제로 있는 필드**(도메인·설명·순위·점수·테이블명 등)만 근거로 **프로젝트 주제와 실질적으로 관련 있는 테이블만** 선별한다.

판단 기준:
- 테이블명·도메인·설명 스니펫이 프로젝트 주제와 직접 연관되는가?
- 범용/관리용 테이블(로그, 배치, 시스템 설정 등)은 제외
- 관련성이 명확하지 않으면 제외 (누락보다 정확도 우선)

선별한 테이블마다 **2~4문장「추천 이유」**만 작성한다. (이유는 `--reasons` JSON에만 넣고, 사용자 채팅에 장문·JSON 덤프를 풀지 않는다.)

이유 작성 기준:
- 프로젝트 목적에 어떻게 기여하는가
- 도메인·설명 스니펫의 어떤 부분이 관련성을 뒷받침하는가
- 구체적이고 간결하게 (예: "재고 수불 이력을 담고 있어 재고 수준 예측 모델의 학습 데이터로 활용 가능")
- **금지:** 시스템 내부 구현, API 경로·엔드포인트 이름, "휴리스틱", "알고리즘", "점수화", "검색 엔진", "LLM", 모델명, 사용자에게 보이기 부적절한 개발 용어

선별한 테이블명 목록과 이유를 내부적으로 확보한다 (사용자에게 목록을 보여주지 않는다).

#### 에이전트에 줄 원샷 프롬프트 템플릿 (1단계 JSON 붙여넣기)

에이전트가 1단계 exec 결과(JSON)를 같은 턴에서 볼 수 있을 때, 아래를 채워 한 번에 요청한다. `…`만 실제 값·JSON으로 바꾼다.

```
역할: 유진홈센터 DW 메타데이터 카탈로그 도우미.

규칙:
- 아래 「검색 JSON」의 results[].table 값만 테이블명으로 사용한다. 새 이름을 만들지 않는다.
- 프로젝트: 「…」
- 사용자 요청 원문: 「…」
- 최대 …개 테이블만 고른다.
- 각 picks[].reason은 2~4문장 한국어. PDF의「테이블별 추천 이유」표에 들어갈 문장으로 쓴다.
- reason에는 그 JSON에 실제로 있는 필드만 근거로 인용한다. JSON에 없는 수치·문장 금지.
- 금지: API 경로·엔드포인트, "휴리스틱", "알고리즘", "점수화", "검색 엔진", "LLM", 모델명 등 개발/시스템 내부 용어.

「검색 JSON」
(여기에 1단계 --search-json-only 의 stdout JSON 전체를 붙여넣는다)

출력: 아래 JSON 한 덩어리만. 마크다운 코드펜스·설명 문장 금지.
{"picks":[{"table":"테이블명_정확히","reason":"선택 이유"}]}
```

### 3단계 — summary 작성 (PDF일 때만)

**▶ PDF 형식일 때:**  
아래 `--summary` 작성 규칙에 따라 한국어 산문 3~5문장을 작성한다.  
**채팅에 직접 출력하지 않는다. 스크립트가 자동으로 텔레그램에 전송하므로, 반드시 4단계 exec의 `--summary "..."` 인자에만 넣어야 한다.**  
채팅에 먼저 출력하면 그 턴에서 exec를 실행할 수 없게 되어 PDF가 전송되지 않는다.

**▶ CSV 형식일 때:** 이 단계를 건너뛰고 바로 4단계로 이동한다.

### 3.5단계 — 추천 구성안 작성 (PDF일 때만)

선별된 테이블과 그 reasons 텍스트를 근거로, 고객이 실제로 구현할 수 있는
추천 유형별 테이블 조합을 작성한다.
**채팅에 직접 출력하지 않는다. 반드시 4단계 exec의 `--recommendation $'...'` 인자에만 넣어야 한다.**
채팅에 먼저 출력하면 그 턴에서 exec를 실행할 수 없게 되어 PDF가 전송되지 않는다.

출력 형식 (불릿 1개 + 이유 1~2문장 세트를 조합 수만큼 반복):
```
추천 구성안:
• {추천 유형}: {TABLE_A}[ + TABLE_B ...]
{이 조합이 왜 유용한지 1~2문장}
• {추천 유형}: {TABLE_A}[ + TABLE_B ...]
{이 조합이 왜 유용한지 1~2문장}
...
```

작성 규칙:
- 소재: 선별된 테이블 목록과 각 reasons 텍스트만 사용
- 추천 유형은 비즈니스 언어로 (예: "개인화 추천", "함께 산 상품 추천")
- 하나의 유형에 여러 테이블이 필요하면 ` + `로 연결
- **각 불릿 바로 다음 줄에 반드시 이유 1~2문장을 쓴다. 이유 없는 불릿은 오답이다.**
- 이유는 reasons 텍스트에서 근거를 가져와 비즈니스 언어로 쓴다 (내부 구현 용어 금지)
- 선별된 테이블에 없는 이름을 만들어 넣는 것은 금지
- CSV 형식일 때: 이 단계를 건너뛰고 바로 4단계로 이동

### 4단계 — export exec

선별한 테이블명과 이유를 `--tables`, `--reasons` 인자로 넘겨 export한다. **PDF 형식일 때는 3단계에서 내부적으로 작성한 텍스트를 그대로 `--summary "..."` 에 넣는다.** `--summary`를 `--tables`보다 앞에 적는다. (작성한 텍스트를 변경하거나 새로 쓰지 않는다.)

PDF 형식일 때는 3.5단계에서 작성한 추천 구성안 텍스트를 `--recommendation $'...'` 에 그대로 넣는다 (ANSI-C 인용, 줄바꿈 보존).

```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_pdf.py {chat_id} --summary "…3~5문장 한국어 산문…" --tables TABLE_A TABLE_B ... --reasons '{"TABLE_A": "이유 텍스트", "TABLE_B": "이유 텍스트"}' --recommendation $'추천 구성안:\n• {추천 유형}: TABLE_A + TABLE_B\n• ...' --format pdf --project "프로젝트명" --account ehcmall
```

CSV 형식:
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py {chat_id} --tables TABLE_A TABLE_B ... --reasons '{"TABLE_A": "이유 텍스트", "TABLE_B": "이유 텍스트"}' --format csv --project "프로젝트명" --account ehcmall
```

**예 (추천시스템, PDF, 선별된 테이블 3개) — 3단계 → 3.5단계 → 4단계 순서:**

**(3단계 — 내부 작성, 채팅 출력 안 함):**
```
[내부 텍스트] 이번 리포트는 추천시스템 구축에 필요한 핵심 데이터를 중심으로 구성했습니다. 상품 속성과 회원 구매 이력, 실제 주문 데이터를 함께 활용하면 개인화 추천 모델을 학습하고 검증하는 데 충분한 기반을 갖출 수 있습니다. 각 테이블은 도메인 메타데이터 카탈로그에서 추천 주제와 직접 연관되는 것만 선별했으며, 아래 표에서 세부 구성과 추천 이유를 확인할 수 있습니다.
```

**(3.5단계 — 내부 작성, 채팅 출력 안 함; 각 불릿 바로 아래에 이유 1~2문장 필수):**
```
[내부 텍스트]
추천 구성안:
• 개인화 추천: ITEM_INFO + MEMBER_INFO
상품 속성과 회원 구매 패턴을 결합해 사용자별 선호 아이템을 예측하는 모델을 학습할 수 있습니다.

```

**(4단계 exec — 3단계 텍스트를 --summary에, 3.5단계 텍스트를 --recommendation에 그대로 넣어 실행):**
```

```

**예 (재고관리, CSV, 선별된 테이블 2개):**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py 123456789 --tables STOCK_MASTER WAREHOUSE_INFO --reasons '{"STOCK_MASTER": "재고 수불 이력을 담고 있어 재고 수준 예측 모델의 학습 데이터로 활용 가능", "WAREHOUSE_INFO": "창고별 입출고 현황을 포함해 재고 이동 경로 분석에 필요"}' --format csv --project "재고관리 최적화" --account ehcmall
```

#### `--summary` 텍스트 작성 규칙 (PDF 전용)

이 규칙으로 작성한 텍스트를 **3단계**에서 채팅에 먼저 출력하고, 동일 텍스트를 **4단계** exec의 `--summary`에 그대로 넣는다.

- **소재**: 1단계 `--search-json-only` JSON의 `description_snippet`과 직접 작성한 `reasons` 텍스트.
- **분량**: 한국어 산문 3~5문장, 200~1000자.
- **목적**: "왜 이 테이블들을 골랐는가, 이 데이터로 무엇을 할 수 있는가"를 독자에게 한눈에 전달.
- **금지**: API 경로·엔드포인트명·LLM·알고리즘·점수화 등 내부 구현 용어.
- **금지**: 선별된 테이블명을 이 단락에 나열하는 것 (아래 표에 이미 있음).
- CSV 형식에는 `--summary`를 전달하지 않는다 (스크립트가 무시하지만, 명령을 간결하게 유지한다).

명령 작성 규칙:
- `--tables` 다음에 테이블명을 **공백으로 분리**해 나열 (따옴표 X).
- `--reasons` 값은 **작은따옴표**로 감싼다. JSON 값 안의 작은따옴표는 `'`로 대체한다.
- `--summary` 값은 **큰따옴표**로 감싼다. 산문 안에 작은따옴표가 있어도 그대로 쓸 수 있다.
- 프로젝트명은 공백 포함 시 반드시 `--project "..."` 큰따옴표로 감싼다.
- exit ≠ 0 이면 stderr 내용을 인용해 안내한다.

## [도메인 전체 — --domain 흐름]

사용자가 특정 도메인의 **전체 테이블**을 요청할 때 사용한다.
`/v1/tables?domain=...` API를 직접 호출하므로 타 도메인 테이블이 섞이지 않는다.
키워드 검색(`--search-json-only`)을 사용하면 설명에 도메인명이 언급된 타 도메인 테이블이 포함되므로 반드시 이 흐름을 써야 한다.

**▶ 1단계 — 도메인 테이블 목록 조회:**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py --search-json-only --domain {도메인명}
```
stdout 형식:
```json
{"domain": "재고", "results": [{"table": "TABLE_A", "domain": "재고", "rank": 1, ...}]}
```

**▶ 2단계 — 대화 모델 선별 (선별이 필요한 경우에만):**
도메인 전체를 요청한 경우 원칙적으로 전 테이블을 포함하지만, 테이블 수가 매우 많으면(30개 초과) 범용·로그·임시 테이블을 제외하고 선별한다.

**▶ 3단계·3.5단계** — PDF일 때 summary·추천 구성안 내부 작성 (채팅 출력 금지, 필터링 ON과 동일 규칙 적용)

**▶ 4단계 — export exec:**

선별 없이 전체를 포함할 때는 `--domain`만 사용 (가장 단순):
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_pdf.py {chat_id} --domain {도메인명} --summary "..." --recommendation $'...' --format pdf --project "{도메인명} 도메인 전체" --account ehcmall
```

선별한 경우에는 `--tables`로 지정:
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_pdf.py {chat_id} --tables TABLE_A TABLE_B ... --reasons '{...}' --summary "..." --recommendation $'...' --format pdf --project "{도메인명} 도메인" --account ehcmall
```

**예 (재고 도메인 전체, PDF):**

**(1단계 exec):**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py --search-json-only --domain 재고
```

**(3단계 채팅 출력):**
```
리포트 요약: 이번 리포트는 재고 도메인에 속한 전체 테이블을 대상으로 구성했습니다. …
```

**(3.5단계 채팅 출력 — 이유 필수):**
```
추천 구성안:
• 재고 현황 분석: IN_LOC_WMS_CMP + IN_LOC_INVNTRY
사업장·상품별 재고 수량과 위치 정보를 결합해 현재 재고 상태를 파악할 수 있습니다.
…
```

**(4단계 exec):**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_pdf.py 7703815236 --domain 재고 --summary "이번 리포트는…" --recommendation $'추천 구성안:\n• 재고 현황 분석: IN_LOC_WMS_CMP + IN_LOC_INVNTRY\n이유 문장.' --format pdf --project "재고 도메인 전체" --account ehcmall
```

## [필터링 OFF — 단일 exec]

1단계 없이 기존 방식대로 키워드로 바로 export한다.

**▶ PDF 형식일 때 (이 단계를 건너뛰면 오답):**  
아래 `--summary` 작성 규칙에 따라 한국어 산문 3~5문장을 **내부적으로 작성**한다. **채팅에 출력하지 않는다** — 출력하면 그 턴에서 exec를 실행할 수 없게 된다.

작성할 텍스트 형식:
```
리포트 요약: {3~5문장 한국어 산문}
```

작성한 텍스트를 그대로 `--summary`에 넣어 exec를 실행한다. `--summary`를 키워드 바로 뒤, 다른 옵션보다 앞에 적는다.

**▶ CSV 형식일 때:** 바로 아래 exec를 실행한다.

PDF:
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_pdf.py {chat_id} 키워드1 [키워드2 키워드3] --summary "…3~5문장 한국어 산문…" --format pdf --project "프로젝트명" --account ehcmall
```

CSV:
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_tables.py {chat_id} 키워드1 [키워드2 키워드3] --format csv --project "프로젝트명" --account ehcmall
```

**예 (추천시스템, PDF, 필터링 없이) — 내부 작성 후 exec 순서:**

**(--summary에 넣을 텍스트 내부 작성 — 채팅 출력 안 함):**
```
[내부 텍스트] 이번 리포트는 추천시스템 구축에 활용 가능한 상품·회원·주문 관련 테이블을 도메인 메타데이터 카탈로그에서 수집해 정리한 것입니다. 각 테이블의 도메인 분류와 설명을 바탕으로, 구매 이력 및 상품 속성 데이터를 결합해 개인화 추천 모델의 학습 데이터로 활용할 수 있습니다. 아래 목록에서 세부 스펙과 컬럼 구성을 확인하시기 바랍니다.
```

**(exec — 위 텍스트를 --summary에 그대로 넣어 실행):**
```
exec: python3 $EHCMALL_BOT_DIR/scripts/export_pdf.py 123456789 상품 회원 주문 --summary "이번 리포트는 추천시스템 구축에 활용 가능한 상품·회원·주문 관련 테이블을 도메인 메타데이터 카탈로그에서 수집해 정리한 것입니다. 각 테이블의 도메인 분류와 설명을 바탕으로, 구매 이력 및 상품 속성 데이터를 결합해 개인화 추천 모델의 학습 데이터로 활용할 수 있습니다. 아래 목록에서 세부 스펙과 컬럼 구성을 확인하시기 바랍니다." --format pdf --project "추천시스템 구축" --account ehcmall
```

#### `--summary` 텍스트 작성 규칙 (PDF 전용, 필터링 OFF)

이 규칙으로 작성한 텍스트를 **채팅에 먼저 출력**하고, 동일 텍스트를 exec의 `--summary`에 그대로 넣는다.

- **소재**: 프로젝트명·키워드·사용자 요청 문맥에서 이 데이터로 무엇을 할 수 있는지.
- **분량**: 한국어 산문 3~5문장, 200~1000자.
- **목적**: "왜 이 도메인·키워드로 검색했는가, 이 데이터로 무엇을 할 수 있는가"를 독자에게 한눈에 전달.
- **금지**: API 경로·엔드포인트명·LLM·알고리즘·점수화 등 내부 구현 용어.
- **금지**: 테이블명을 이 단락에 나열하는 것 (아래 표에 이미 있음).
- CSV 형식에는 `--summary`를 전달하지 않는다.

키워드는 위치 인자로 **공백 분리** 1~3개 (4개 이상이면 앞 3개만 사용됨).

## 결과 안내

exec stdout 마지막 부분에 다음 줄들이 출력된다:
- `파일 저장 경로: ~/Downloads/ehcmall-reports/...`
- `TABLES_COUNT={숫자}`
- `FORMAT={csv|pdf}`
- `PROJECT={프로젝트명}`

이 값들을 그대로 사용해 아래 형식으로 답한다.

**[필터링 ON] — 선택 이유 포함:**

```
📁 «{PROJECT}» 관련 테이블 총 {TABLES_COUNT}개 (선택 이유 포함)가 포함된 {FORMAT 대문자} 파일을 전송했습니다.

• 저장 경로: {파일 저장 경로 그대로}
```

**[필터링 OFF] — 선택 이유 없음 (변경 없음):**
```
📁 «{PROJECT}» 관련 테이블 총 {TABLES_COUNT}개가 포함된 {FORMAT 대문자} 파일을 전송했습니다.

• 저장 경로: {파일 저장 경로 그대로}
```

## 주의사항
- 선별된 **모든** 테이블이 파일에 빠짐없이 포함된다 (일부 발췌 금지).
- CSV 컬럼 순서는 고정: `table_name, domain, rank, score, row_count, column_count, data_size_mb, period, description, columns, selection_reason`
- 컬럼 직렬화 형식: `CODE(한글라벨);CODE2(한글라벨2);CODE3` — 라벨이 없으면 코드만.
- PDF 본문 표(순위·테이블명·도메인·점수·행 수·컬럼 수·설명)와 컬럼 상세 표의 값은 **전부 `/v1/explain` JSON**에서만 온다. **추천 이유**만 LLM이 쓰며, PDF에서는 **「테이블별 추천 이유」표**(테이블명 | 추천 이유)에만 넣는다.
- PDF는 테이블 수가 많으면 수백 페이지가 될 수 있으나, 이는 의도된 동작이다.
- 봇 토큰은 `~/.openclaw/openclaw.json` → `channels.telegram.accounts.{account}.botToken`에서 자동 로드.
- 항상 한국어로 답변한다.
- 터미널에서 사람이 읽을 때만 `--search-only`(텍스트 표)를 쓰고, 에이전트 1단계는 **`--search-json-only`** 만 쓴다.
